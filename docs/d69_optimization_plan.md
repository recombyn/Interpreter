## 2. 失败模式归类



### 2.1 匹配 / 触发（产品回归）

1. `合不合法` **被预处理破坏（P0）**
  - 输入：`试用期六个月合不合法`  
  - `preprocess` 结果：`试用期六个月和不合法`（「合」→「和」）  
  - 直接 `decode` 模块可命中 D69；经 `turn`/`Para.decode` 则落到 **D57「是的」**。  
  - `rules.tm` 已声明触发 `合不合法`，`match_judge` 也正常；根因在 **E 段字形/邻接修复**，不是 D69 规则表缺失。
2. **极性表层与触发对齐（已处理为评分同义，非缺陷）**
  - `合规吗` → 答「合规/不合规」；`可以吗` → 「可以/不可以」。  
  - 评测勿只认「合法」二字。



### 2.2 条件 / 档位

- 有合同期限：二元合法/不合法 + 出处，**28/28**。  
- 无合同：条件叙事「在下列情况下合法」+「不得超过…」，超 6 月绝对上限「不合法」，**12/12**。  
- 当前 **不必** 为档位再扩 DSL。



### 2.3 多问 / 长句

- 双 D69、`另外`、长前缀剥离均通过。  
- 组合缺口里「A 且 B 都合法吗」仍走 D21，属 **组合语义**，不是 multi-fire 剥离子句能力问题。



### 2.4 组合缺口（`tag=gap`，预期内）


| 现象    | 代表用例                    | 现状            | 升级方向                      |
| ----- | ----------------------- | ------------- | ------------------------- |
| 合取否定  | 试用期六个月**且未**书面约定严格合法吗   | D21「不是」       | `not(书面约定)` / also 键否定    |
| 前缀否定  | **没有**书面约定试用期六个月合法吗     | 仍按普通 D69 条件合法 | 话题前 `not` 作用域             |
| 无规则主题 | **劳务派遣**试用期三个月合法吗       | 当普通试用期答       | 主题隔离或独立 rule；未知则 miss     |
| 枚举析取  | 固定期限**或**无固定期限合同类型合法吗   | D69.ask       | `any(许可成员)`               |
| 时长析取  | 试用期六个月**或者**七个月合法吗      | D21           | `any(duration)`（勿做完整布尔）   |
| 多主题全称 | 竞业二年**且**试用期六个月**都**合法吗 | D21           | `all(子判定)`                |
| 值否定   | 试用期**不是**六个月合法吗         | 弱/错路径         | `not(value)` → ask/refuse |


Gap 十条全部 `gap_hit`（有应答、未崩溃）；**不算 failed**。

## 3. D69 组合优化方案（系统 vs `rules.tm`）



### 3.1 分工原则


| 层                      | 负责                                                            | 不负责                 |
| ---------------------- | ------------------------------------------------------------- | ------------------- |
| **系统（judge / decode）** | 解析有限组合算子；求值顺序；缺槽 ask；与 multi-fire 衔接；拒绝发明                     | 开放域布尔代数、任意嵌套、自然语言推理 |
| `rules.tm`**（声明）**     | 主题、算子、`上限/许可`、also 键、触发词；**可选** 声明 `any`/`all`/`not` 作用在哪一类键上 | 写 Python；枚举全部合法句子   |
| `limits.tm` **/ 用户事实** | 数值上限、枚举许可、书面约定等 **of** 事实                                     | 组合语法                |


**明确不做：完整布尔代数 DSL**（无任意 `∧∨¬` 嵌套、无括号优先级语言）。只加 **声明式、浅层** 的 `any` / `not` / `all` 三件套，覆盖高频劳动法问法。

### 3.2 建议增加的声明式算子（浅层）

```text
# 示意（具体语法可落在 rules.tm 一行扩展，由 judge 解释）
# any:  子值命中其一即按原 op 判定（枚举成员 / 时长列表）
# all:  多个 theme 判定都成立才答「都合法」；否则点名失败项
# not:  仅作用于 also 键或紧邻否定词（未/没有/不是），不开放任意子公式
```

求值约定（保持可预测）：

1. 先剥 multi-fire 子句；组合作仅在 **单子句** 内解释。
2. `not` 只认固定否定词表 + also 键 / 枚举值，不认修辞。
3. `any`/`all` **深度 ≤ 1**（列表元素，不再嵌套）。
4. 解析失败 → 维持今日行为（D69.ask / REN2 / 拒答），**不** 瞎答「是的」。



### 3.3 三个能消掉的 gap 用例（落地后应收口）


| #   | 用例                  | 声明/系统行为                                        | 期望口语                  |
| --- | ------------------- | ---------------------------------------------- | --------------------- |
| 1   | `固定期限或无固定期限合同类型合法吗` | `any` over 许可枚举                                | 二者均在许可内 →「合法」（或分说都合法） |
| 2   | `竞业限制二年且试用期六个月都合法吗` | `all` 联立两个已有 rule                              | 两段都合法 →「都合法」+ 可带双出处   |
| 3   | `试用期六个月且未书面约定严格合法吗` | `严格` 规则的 also=`书面约定` + 表面 `未/没有` → `not(also)` | 「不合法」或「未书面约定则不严格合法」   |


其余 gap（劳务派遣主题、时长 or 六个月/七个月混判）可作 **P1/P2** 样例，不阻塞三件套落地。

### 3.4 与现有能力的关系

- **保留**：tier 矩阵、条件叙事、触发极性、合取 ask（缺书面约定时）、multi-fire。  
- **先修 P0**：预处理勿把「合不合法」改成「和不合法」（白名单触发整词，或禁止「合→和」在 `*合法` 前）。  
- **再加** 浅层 `any`/`all`/`not`，用上表 3 条作验收，而不是新语言。

## 4. 优先级



### P0（立刻）

1. **修复「合不合法」被 preprocess 改写**（触发整词保护 / 邻接替换黑名单）。
2. 回归：`试用期六个月合不合法` / `试用期七个月合不合法` → D69，且极性正确。
3. 评测保持触发对齐的极性同义（合法↔合规/可以）。



### P1（组合浅层）

1. `rules.tm` + judge：`any`（枚举或）、`all`（多主题都…）、`not`（also / 未书面约定）。
2. 验收消掉 §3.3 三条 gap。
3. 「没有书面约定…合法吗」：前缀 `not` 作用域（可与严格合取共用 not 词表）。



### P2（主题与边界）— **已落地**（2026-08-21）

1. 劳务派遣等 **无 rule 主题** → miss/REN2（`unknown_prefix`），禁止静默落到「试用期」通用档。前缀白名单：`劳务派遣` / `非全日制`。
2. 时长 `或者` 混合法/非法 → `D69.ask`「请问试用期是六个月还是七个月」；同极性则直接答。`不是六个月` → ask。
3. `A并且B合法吗`（无「都」）→ 浅层 `all_topics`（口语「都合法」）；`既没有书面约定又…严格合法吗` → `not_also`。
4. 门禁：`eval_d69_100` → **non_gap 100/100 failed=0**；原 composition_gap 10 条已全部升为 `p2_*` gated。
