# CNI 使用与设计指南

[English](guide.en.md) · 中文

符号规则引擎：人话进、事实出。**无大模型**。

世界按解码表落盘：`isa` / `located` / `has` / `event`+`of(角色…)`。  
底层不把 `located`/`has` 改写成 `of(located,…)` / `of(has,…)`。

**规则分工以下表为准。** 表1逐条 → [规则全表.md](规则全表.md)。英文 → [guide.en.md](guide.en.md) / [rules.en.md](rules.en.md)。

## 分工与流水线

- **表1（内核）**：D / E / F41–50 / G / I1–3 / I7–8 / I10 / RO·WC·QP·MEM·REN，共 **110**；另加约定扩展 D66/D67/D69/MEM4/I11。
- **表2（用户）**：F1–40 + H1–10 + I4–6 + I9，共 **54**，在 `knowledge/user/user_dict.tm`。

```
输入 → E → user_dict(表2) → F41–50 → G → I(表1) → D → 内核(RO/WC/QP/MEM/REN) → 输出
```

## 设计架构

```
用户输入
    │
    ▼
┌─────────── RO 路由 ───────────┐
│  教/记住/学习/记 或 teach？     │
│   是 → hear（写）  否 → turn（读）│
└──────────────┬────────────────┘
               ▼
┌─────────── 预处理 ────────────┐
│  E → user_dict → F41–50 → G → I │
│  I 命中 → 直接口头回复，结束     │
└──────────────┬────────────────┘
               ▼
┌─────────── D 解码 ────────────┐
│  D66/D67 字面早退；短问 MEM4→D67；否则 lex+D表 │
│  写 tell / 读 find·yesno       │
└──────────────┬────────────────┘
               ▼
┌─────────── 世界 ──────────────┐
│  isa / located / has / event… │
│  规则推理深≤2                  │
└──────────────┬────────────────┘
               ▼
┌─────────── REN 输出 ──────────┐
│  form/lex → 人话               │
│  REN1 缺模板裸显；REN2 查空话术 │
└───────────────────────────────┘
```

## 世界事实形态

```text
isa(电脑, 机器)
located(电脑, 桌上)          # 原生谓词
has(我, 电脑)                # 原生谓词
of(kind, e.1, invent)        # 事件角色仍用 of
of(content, 静夜思, 床前明月光)
# D67：按实体 O(1) 取 content（内存索引 ∪ knowledge/user/.content 分片）
# MEM4：短追问 + 实体钉 → 补全为 D67（无开放检索规则）
```

## 已知能力边界（D 层）

## 回复模式（是非问话术）

在 `knowledge/user/config.tm`：

```tm
reply_mode default   # 是的 / 不是
# reply_mode bool    # true / false
# reply_mode zh_bool # 是 / 否
```

或在 `knowledge/user/form.tm` 单独覆盖：`out yes true`。  
只影响是非问（D21 等）的 yes/no；**D67 仍回正文**，不会压成布尔。

## 示例

```bash
python -m cni teach "电脑是机器"
python -m cni reply "电脑是什么"
python -m cni teach "静夜思的内容是床前明月光"
python -m cni reply "静夜思的内容是什么"
python -m cni.tools.sync_user_docs --force
python -m cni reply "第20行的内容是什么"
python -m cni reply "那呢"   # MEM4 → 同一实体再走 D67
```

表2 映射：`knowledge/user/user_dict.tm`（`map 原文 标准词`）。

### 阈值判定（D69）

语法见上文 **「用户层 tm 语法」**。示例：

```tm
# knowledge/user/劳动法/rules.tm
rule 试用期 le 上限 合法吗|合规吗|可以吗
rule 合同类型 in 许可 合法吗|合规吗|可以吗
# 合取示例: rule 试用期 le 上限&书面约定 合法吗
# 多档: tier 试用期 3 12 1
```

```bash
# 文档进库（行检索）+ 条号映射 + 阈值事实（需已有 rules.tm）
python -m cni.tools.sync_user_docs --force
python -m cni.tools.compile_labor_articles --write   # → 劳动法/article.maps.tm
python -m cni.tools.compile_limits --write            # → 劳动法/limits.tm（半自动）
python -m cni reply "试用期六个月合法吗"     # D69 → 是的（见劳动法第84行）
python -m cni reply "合同一年试用期二个月合法吗"  # 多档：一年档上限2月
python -m cni reply "试用期合法吗"           # D69.ask → 请问试用期几个月？
python -m cni reply "六个月"                 # 续答 → D69
python -m cni reply "试用期六个月严格合法吗" # 合取：需 of(书面约定,…)
python -m cni reply "合同类型固定期限合法吗" # 枚举许可
```

`config.tm`：`judge_cite on|off` 控制是否附出处。  
无上限/许可事实 → REN2。不是开放全文检索。`rules.tm` / `tier` 仍须手写，见 **「工具生成 vs 手写」**。

## 设计边界

- 无大模型；未教过的世界知识不猜
- 表1内核 / 表2用户词典，不混放
- 闲聊路径不写开放事实
- 落盘：`isa` / `located` / `has` / `of(角色…)`；不擅自加未声明谓词
- I11 不做诗词赏析
